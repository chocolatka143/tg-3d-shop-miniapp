# Личный кабинет: статусы заказов (черновик)

Схема ЛК для Mini App «Бубер 3D»: клиент видит свои заказы и статус, исполнитель меняет статус в Google Таблице.

**Сейчас:** документ + stub UI + расширенный Apps Script.  
**Пока нет:** проверка `initData` Telegram на сервере, пуш при смене статуса, полноценный бэкенд.

Связанные файлы: `orders-apps-script/Code.gs`, `SETUP-ORDERS.md`, экран «Мои заказы» в `src/main.js`.

---

## 1. Статусы заказа

Цепочка (исполнитель правит колонку **Статус** в таблице):

| Статус | Кто ставит | Смысл для клиента |
|--------|------------|-------------------|
| **Новый** | автоматически при создании | Заявка принята, ждём подтверждения |
| **Подтверждён** | исполнитель | Согласовали состав / цену / способ получения |
| **В печати** | исполнитель | Печатаем |
| **Готов** | исполнитель | Можно забирать / отправляем |
| **Выдан** | исполнитель | Закрыт успешно |
| **Отменён** | исполнитель | Отмена (любой момент до «Выдан») |

Переходы по смыслу:

```
Новый → Подтверждён → В печати → Готов → Выдан
  └──────────────→ Отменён ←──────────────┘
```

Допустимо: `Новый → Отменён`, `Подтверждён → Отменён`, `В печати → Отменён`.  
Нежелательно менять статус после **Выдан** / **Отменён** (кроме исправления опечатки).

В MVP клиент **не** меняет статус сам — только смотрит.

## 2. Колонки листа «Заказы»

Рекомендуемый порядок заголовков (строка 1):

| # | Колонка | Источник | Пример |
|---|---------|----------|--------|
| A | Дата | Apps Script (МСК) | `02.10.2026 21:30` |
| B | order_id | Mini App при оформлении | `ord_1727…_a3f2` |
| C | telegram_user_id | `Telegram.WebApp.initDataUnsafe.user.id` | `123456789` |
| D | Имя | форма checkout | `Марк` |
| E | Телефон | форма | `+7…` |
| F | Username | форма / TG | `username` |
| G | Оплата | `sbp` / `cash` → подпись | `СБП` |
| H | Комментарий | форма | … |
| I | Состав | текст из items | … |
| J | Сумма | number | `1800` |
| K | Статус | `Новый` при создании; дальше вручную | `В печати` |

**Важно:** `telegram_user_id` — ключ «чьи это заказы» для ЛК. Без него список по пользователю не собрать.

Если лист уже создан со старыми заголовками (без `order_id` / `telegram_user_id`):

1. Вставьте две колонки после «Дата» и назовите их `order_id`, `telegram_user_id`, **или**
2. Создайте новый лист / таблицу и заново вставьте актуальный `Code.gs` (скрипт сам проставит заголовки на пустом листе).

После смены кода Apps Script: **Развернуть → Управление развёртываниями → новая версия**.

## 3. Apps Script API

### POST — создать заказ (уже есть)

`POST …/exec?key=WEBHOOK_SECRET`  
Тело: `Content-Type: text/plain` + JSON:

```json
{
  "order_id": "ord_…",
  "telegram_user_id": 123456789,
  "name": "…",
  "phone": "…",
  "username": "…",
  "payment": "sbp",
  "comment": "…",
  "items": [ … ],
  "total": 1800,
  "createdAt": "2026-10-02T18:30:00.000Z"
}
```

Ответ: `{ "ok": true, "telegram": true/false, "order_id": "…" }`.  
В лист пишется строка со статусом **Новый**.

### GET — список заказов пользователя (для ЛК)

```
GET …/exec?key=WEBHOOK_SECRET&userId=123456789
```

Ответ:

```json
{
  "ok": true,
  "orders": [
    {
      "order_id": "ord_…",
      "date": "02.10.2026 21:30",
      "telegram_user_id": "123456789",
      "name": "…",
      "phone": "…",
      "username": "…",
      "payment": "СБП",
      "comment": "…",
      "items": "…",
      "total": 1800,
      "status": "Новый"
    }
  ]
}
```

Без `userId` (только `key`) — health-check: `{ ok, service, sheet, time }` (как раньше).

Фильтр: строки, где колонка `telegram_user_id` совпадает с `userId` (сравнение как строки). Сортировка: новые сверху (с конца листа).

## 4. Безопасность

| Слой | MVP (сейчас) | Позже |
|------|--------------|--------|
| Секрет вебхука | `?key=WEBHOOK_SECRET` | то же + ротация |
| Кто я в Mini App | `initDataUnsafe.user.id` с клиента | **проверка подписи `initData`** на сервере (HMAC с bot token) |
| Чтение чужих заказов | теоретически: подставить чужой `userId` в GET | после verify initData — брать id только из проверенных данных |
| CORS | POST как `text/plain` | при необходимости прокси на своём домене |

**Итог для MVP:** передаём `telegram_user_id` из WebApp — удобно для демо.  
**Перед публичным ЛК с живыми клиентами:** обязательно verify `initData` (в Apps Script или на маленьком бэкенде). Иначе любой, кто знает URL+key, может запросить заказы чужого id.

Секреты (`BOT_TOKEN`, `CHAT_ID`, `WEBHOOK_SECRET`) — только в свойствах скрипта, не в git.

## 5. Mini App (stub)

- В шапке / навигации: **«Мои заказы»**.
- Пока webhook в `SHOP.orderWebhookUrl` пустой и локальных заказов нет → текст: *«Заказы появятся после подключения таблицы»*.
- Если в `localStorage` (`tg3d_orders_v1`) есть заказы с этого устройства → показать их со статусом **Новый** (офлайн-заглушка).
- При оформлении в payload уходят `order_id` и `telegram_user_id`.
- Следующий шаг UI: `GET` с `userId` + `key` и отрисовка статусов с таблицы (когда таблица подключена дома).

Опционально позже: бот шлёт клиенту сообщение при смене статуса (триггер `onEdit` в таблице или ручная кнопка в скрипте).
