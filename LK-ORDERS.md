# Личный кабинет: статусы заказов

Схема ЛК для Mini App «Бубер 3D»: клиент видит свои заказы и статус, исполнитель меняет статус в Google Таблице.

**Сейчас:** документ + UI «Мои заказы» + Apps Script (POST create / POST list).  
**Пока нет:** проверка `initData` Telegram на сервере, полноценный бэкенд.
**Есть:** пуш клиенту в Telegram при смене колонки «Статус» (installable `onEdit` → `onOrdersStatusEdit`).

Связанные файлы: `orders-apps-script/Code.gs`, `SETUP-ORDERS.md`, экран «Мои заказы» в `src/main.js`.

## 1. Статусы заказа

Цепочка (исполнитель правит колонку **Статус** в таблице):

| Статус | Кто ставит | Смысл для клиента |
|--------|------------|-------------------|
| **Новый** | автоматически при создании | Заявка принята, ждём подтверждения |
| **Подтверждён** | исполнитель | Согласовали состав / цену / способ получения |
| **В печати** | исполнитель | Печатаем |
| **Готов** | исполнитель | Можно забирать / отправляем |
| **Выдан** | исполнитель | Закрыт успешно |
| **Отменён** | исполнитель | Отмена (любой момент до «Выдан») |

Переходы по смыслу:

```
Новый → Подтверждён → В печати → Готов → Выдан
  └──────────────→ Отменён ←──────────────┘
```

Допустимо: `Новый → Отменён`, `Подтверждён → Отменён`, `В печати → Отменён`.  
Нежелательно менять статус после **Выдан** / **Отменён** (кроме исправления опечатки).

В MVP клиент **не** меняет статус сам — только смотрит.

### Как сменить статус (исполнителю)

1. Откройте Google Таблицу → лист **«Заказы»**.
2. Найдите строку заказа (по `order_id`, телефону или дате).
3. В колонке **Статус** впишите одно из: `Новый`, `Подтверждён`, `В печати`, `Готов`, `Выдан`, `Отменён` (точно так, без лишних пробелов).
4. Клиенту уйдёт пуш в Telegram (если настроен триггер и есть `telegram_user_id` + `/start`).
5. В Mini App клиент может нажать **«Обновить статусы»** на экране «Мои заказы» — увидит новый бейдж.

Других кнопок в MVP нет: статус = значение ячейки в таблице.

## 2. Колонки листа «Заказы»

Рекомендуемый порядок заголовков (строка 1):

| # | Колонка | Источник | Пример |
|---|---------|----------|--------|
| A | Дата | Apps Script (МСК) | `02.10.2026 21:30` |
| B | order_id | Apps Script при создании строки | `1000`, `1001`… (старые `ord_`/`ping-` остаются) |
| C | telegram_user_id | `Telegram.WebApp.initDataUnsafe.user.id` | `123456789` |
| D | Имя | форма checkout | `Марк` |
| E | Телефон | форма | `+7…` |
| F | Username | форма / TG | `username` |
| G | Оплата | `sbp` / `cash` → подпись | `СБП` |
| H | Комментарий | форма | … |
| I | Состав | текст из items | … |
| J | Сумма | number | `1800` |
| K | Статус | `Новый` при создании; дальше вручную | `В печати` |
| L+ | Промокод / Скидка / Сумма до скидки | Apps Script (дописывает колонки) | `B5-AB12`, `90` |

**Важно:** `telegram_user_id` — ключ «чьи это заказы» для ЛК. Без него список по пользователю не собрать.

Если лист уже создан со старыми заголовками (без `order_id` / `telegram_user_id`):

1. Вставьте две колонки после «Дата» и назовите их `order_id`, `telegram_user_id`, **или**
2. Создайте новый лист / таблицу и заново вставьте актуальный `Code.gs` (скрипт сам проставит заголовки на пустом листе).

После смены кода Apps Script: **Развернуть → Управление развёртываниями → новая версия**.

## 3. Apps Script API

Авторизация Mini App: поле `initData`. Админ/curl: секрет в JSON-поле `secret`, либо `?key=`, либо заголовок `X-Webhook-Secret` (для list и GET, не для заказа из магазина).

### POST — создать заказ

`POST …/exec`  
Тело: `Content-Type: text/plain` + JSON:

```json
{
  "initData": "<Telegram.WebApp.initData>",
  "name": "…",
  "phone": "…",
  "username": "…",
  "payment": "sbp",
  "comment": "…",
  "items": [ … ],
  "total": 1800,
  "createdAt": "2026-10-02T18:30:00.000Z"
}
```

Без `initData`: `{ "ok": false, "error": "Откройте магазин из Telegram" }`.  
Ответ при успехе: `{ "ok": true, "telegram": true/false, "order_id": "…" }`.  
`telegram_user_id` в таблицу берётся из проверенного `initData`. Имя, телефон и username обязательны.

### POST — список заказов пользователя (для ЛК, предпочтительно)

`POST …/exec`  
Тело:

Mini App:

```json
{ "action": "list", "initData": "<Telegram.WebApp.initData>" }
```

Админ/curl (свойство скрипта, не клиент):

```json
{ "action": "list", "secret": "<WEBHOOK_SECRET>", "telegram_user_id": 123456789 }
```

Ответ:

```json
{
  "ok": true,
  "orders": [
    {
      "order_id": "ord_…",
      "date": "02.10.2026 21:30",
      "telegram_user_id": "123456789",
      "name": "…",
      "phone": "…",
      "username": "…",
      "payment": "СБП",
      "comment": "…",
      "items": "…",
      "total": 1800,
      "status": "Новый"
    }
  ]
}
```

Фильтр: строки, где колонка `telegram_user_id` совпадает (как строки). Сортировка: новые сверху.

### GET — health / запасной список

```
GET …/exec?key=WEBHOOK_SECRET
GET …/exec?key=WEBHOOK_SECRET&userId=123456789
```

Без `userId` — health-check: `{ ok, service, sheet, time }`.  
С `userId` — тот же массив `orders`, что у POST list.

> **Замечание:** Mini App ходит POST с `initData` в теле. GET с `?key=` — только ручная проверка; на редиректе Google query иногда теряется.

## 4. Безопасность

| Слой | MVP (сейчас) | Позже |
|------|--------------|--------|
| Секрет вебхука | только админ/curl (`secret` / `?key=`), не в Mini App | ротация в свойствах скрипта |
| Кто я в Mini App | **подпись `initData`** (HMAC, bot token), id из проверенных данных | — |
| Чтение чужих заказов | list с `initData` берёт id только из подписи | — |
| CORS | POST как `text/plain` | при необходимости прокси на своём домене |

**Заказы и список из Mini App** принимаются только с валидным `initData` (не старше 1 суток). Без Telegram ответ: «Откройте магазин из Telegram».

Секреты (`BOT_TOKEN`, `CHAT_ID`, `WEBHOOK_SECRET`) — только в свойствах скрипта, не в git.

## 5. Mini App

- В шапке / навигации: **«Мои заказы»**.
- При открытии: `POST { initData, action: "list" }` → бейджи статусов. Id пользователя берётся из `initData`.
- Кнопка **«Обновить статусы»** — повторный запрос.
- Если запрос не удался → fallback на `localStorage` (`tg3d_orders_v1`) со статусом на момент оформления.
- При оформлении в payload уходит `initData` (сырая строка `Telegram.WebApp.initData`), без секрета.

### Пуш при смене статуса

Реализовано в `orders-apps-script/Code.gs`:

1. Вставьте обновлённый `Code.gs` в Apps Script и сохраните.
2. Один раз выполните **`installTrigger()`** (или создайте триггер вручную на `onOrdersStatusEdit` / On edit). См. [orders-apps-script/README.md](orders-apps-script/README.md) §8.
3. Клиент должен сделать боту **`/start`**; в строке заказа нужен **`telegram_user_id`** (из Mini App).
4. Меняете «Статус» в таблице → клиенту уходит сообщение с `order_id` и новым статусом.

Новая версия веб-приложения для пуша не нужна (триггер смотрит на сохранённый код проекта). Новую версию `/exec` — только если правили `doGet`/`doPost`. Mini App менять не требуется.
